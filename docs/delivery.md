# Сдача решения

Чек-лист собран по требованиям кейса к формату сдачи. Проверяем его на этапе Д7, но пункты, которые можно закрыть в первый день, закрываем сразу.

| Требование | Статус | Где в репозитории |
| --- | --- | --- |
| Репозиторий на GitHub с историей работы команды | сделано в Д1 | — |
| Доступ аккаунту `alfa-hack-2026` | сделано в Д1 | [github-setup.md](github-setup.md) |
| Тег или commit hash финальной версии в заявке | Д7 | — |
| README: что за решение, как запустить, что нужно для запуска | сделано в Д1, обновляется | [../README.md](../README.md) |
| Единый воспроизводимый запуск (Docker) | Д1–Д2 | `deploy/`, `compose.yaml` |
| Зафиксированные версии языка и зависимостей | сделано в Д1 | `backend/uv.lock`, `backend/.python-version`, `frontend/package-lock.json`, `frontend/.nvmrc` |
| Перечень сторонних компонентов и лицензий | ведётся с Д1 | [../THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md) |
| Данные в репозитории только синтетические | правило с Д1 | [data.md](data.md), `.gitignore` |
| Описание API и схем данных | Д6 | `/api/docs`, `/api/openapi.json` |
| Внешний стенд с решением | Д7 | [github-setup.md](github-setup.md) |

## Перед отправкой заявки

1. Прогнать `docker compose up -d --build` на чистой машине из свежего клона: без локального `.env`, только `cp .env.example .env` и заполнение ключей.
2. Проверить, что в диффе от начала проекта нет ключей и выгрузок кейса.
3. Обновить `THIRD_PARTY_NOTICES.md` по финальным lock-файлам.
4. Проставить тег на финальный коммит `main` и указать его в заявке.
5. Убедиться, что у `alfa-hack-2026` доступ активен, а не висит приглашением.
