# Новости

Путь материала: сбор → нормализация → дедупликация → разбор моделью. Аналитика Альфа-Банка идёт отдельным входом и встречается с новостями в общей ленте.

## Сбор

Задача A3-01, модуль `app/news/fetch.py`, список источников — [`backend/app/news/sources.yaml`](../backend/app/news/sources.yaml) (путь задаёт `NEWS_SOURCES_FILE`, относительный — от каталога `backend`).

Рекомендованного списка источников у кейса нет: подходят любые законные бесплатные способы. Берём открытые RSS деловых СМИ и регуляторов.

| Источник | Тип | Текст |
| --- | --- | --- |
| Интерфакс, ПРАЙМ, Коммерсантъ — Экономика, Ведомости — Бизнес, Экономика, Финансы | `media` | в ленте только анонс, качаем страницу статьи |
| Российская газета, Forbes | `media` | полный текст есть в ленте |
| Банк России — пресс-релизы и события, Минпромторг | `regulator` | официальная позиция; у событий ЦБ качаем страницу |
| РИА Новости, Коммерсантъ — Все новости | `media`, резерв | обходятся, только пока недоступны основные (`backup_for`) |
| ТАСС, РБК | `media`, выключены | не отвечают из нашей сети, оставлены для стенда |

### Как обходим

- **Расписание.** У каждого источника свой интервал (`interval_minutes`, по умолчанию `NEWS_FETCH_INTERVAL_MINUTES`). Состояние хранится в таблице `news_sources_state`: когда обходили, когда был успех, сколько ошибок подряд, когда обходить в следующий раз.
- **Ошибки.** Если источник не ответил, следующая попытка будет через 5, 10, 20 минут и так далее, но не реже раза в шесть часов. После трёх ошибок подряд источник считается недоступным, и включаются его резервные.
- **Повторы.** Временные ошибки (таймаут, обрыв, 429, 5xx) повторяются дважды с паузой 1 и 2 секунды. Если сервер прислал `Retry-After`, ждём сколько он просит, но не больше минуты. На 4xx не повторяем.
- **Вежливость.** Между запросами к одному сайту — не меньше секунды. Свой `User-Agent` (`NEWS_USER_AGENT`). robots.txt соблюдаем по правилам Google: группа самого точного User-agent, шаблоны `*` и `$`, побеждает самое длинное правило. Стандартный `urllib.robotparser` для этого не годится: он не понимает `*` и правило `Disallow: /?` (оно есть у Коммерсанта) читает как запрет всего сайта. Нет robots.txt — можно обходить, сайт не ответил — не обходим.
- **Без лишних запросов.** Ссылка приводится к одному виду (без `utm_*`, якоря, хост в нижнем регистре). Страницы статей, которые уже сохранены, повторно не качаются.

### Что сохраняем

Таблица `raw_news` — материал как его отдал источник, без обработки: так нормализацию (A3-02) можно пересчитать, не обходя источники заново.

| Поле | Что это |
| --- | --- |
| `raw_id` | `raw:` + хеш ссылки |
| `source_id`, `url`, `guid` | источник, ссылка на первоисточник, id записи в ленте |
| `title`, `summary`, `feed_text` | заголовок, анонс и полный текст, если лента его отдаёт |
| `html` | страница статьи, если источник отдаёт только анонс |
| `published_at`, `fetched_at` | время публикации по ленте и время сбора, UTC |
| `article_status` | `feed_only` — текст из ленты, `fetched` — страница скачана, `robots` — robots.txt запрещает, `failed` — страница не ответила, `too_large` — больше 3 МБ |

### Запуск

```
cd backend
uv run python -m app.news                       # один обход: все источники, которым пора
uv run python -m app.news --source interfax     # один источник вне расписания
uv run python -m app.news --loop                # обходить по расписанию, не выходя
```

Команда печатает отчёт: сколько новых материалов у каждого источника и какие ошибки. Первый обход 21.10.2026 собрал 279 материалов из 11 источников.

## Нормализация

Задача A3-02, модуль `app/news/normalize.py`. Запись `raw_news` превращается в `NewsItem` (схема — [schemas/news_item.schema.json](schemas/news_item.schema.json)) и сохраняется в таблицу `news_items`: ключевые поля отдельными столбцами, весь материал — в `item` (jsonb).

| Поле | Как получаем |
| --- | --- |
| `id` | `news:` + хеш ссылки, тот же, что у записи `raw_news` |
| `title` | заголовок из ленты без HTML-сущностей и лишних пробелов |
| `text`, `fragments` | текст статьи абзацами; каждый абзац — фрагмент `p1`, `p2`… с пометкой «абзац N», на него ссылаются факты и выводы |
| `summary` | анонс из ленты без разметки, если он не повторяет первый абзац |
| `published_at` | дата из ленты в UTC; если её нет или она из будущего — время сбора |
| `source`, `url` | название и лента источника, ссылка на первоисточник |
| `language` | `ru` или `en` по доле кириллицы и латиницы |
| `dedup.content_hash` | хеш слов заголовка и текста без регистра и пунктуации: точные перепечатки совпадут |

Текст статьи ищем по порядку, способ записан в `text_origin`:

1. `feed` — полный текст из ленты (`content:encoded`, `yandex:full-text`);
2. `selector` — абзацы по CSS-селектору источника (`text_selector` в `sources.yaml`);
3. `json_ld` — `articleBody` из JSON-LD страницы; сплошной текст режется на куски по несколько предложений, чтобы на фрагмент можно было сослаться точно;
4. `generic` — общий алгоритм для источника без селектора. Берутся блоки текста без вложенных блоков, их длина засчитывается родителю и вполовину прародителю, и из узла с наибольшим весом берутся его абзацы. Так тело статьи находится без меню и подвала;
5. `summary` или `title` — если страницы нет.

Служебные строки («Читайте также», «Подписывайтесь», «Фото:», «©») и повторы абзацев отбрасываются.

Селекторы проверены 21.10.2026 на сайтах из списка источников. На первом обходе по селектору разобрано 197 статей из 281, по полному тексту ленты — 19, по JSON-LD — 2. Ещё 63 записи остались только с анонсом: у пресс-релизов ЦБ и новостей Минпромторга в анонсе и так полный текст на 2 тыс. символов, а у Российской газеты страницы качаются начиная с этой задачи.

Сырые записи хранятся, поэтому нормализацию можно пересчитать без нового обхода, например после правки селектора:

```
cd backend
uv run python -m app.news normalize          # новые записи raw_news
uv run python -m app.news normalize --all    # все заново
```

## Дедупликация

Задача A3-03, модуль `app/news/dedup.py`, схема сюжета — [schemas/news_story.schema.json](schemas/news_story.schema.json). Одно событие из пяти изданий — одна карточка-сюжет, а ссылки на все публикации сохраняются списком (`NewsStory.items`). Эмбеддингов нет ([ADR 0002](decisions/0002-otbor-bez-embeddingov.md)), поэтому сравниваем лексически, в два шага:

1. **Перепечатка** (`match=exact`) — совпал `content_hash`: слова заголовка и текста те же. В `duplicate_of` — оригинал.
2. **То же событие** (`match=similar`) — косинус TF-IDF не меньше 0,45. Вектор строится по основам слов заголовка (вдвое весомее) и первых двух абзацев. Основа — первые пять букв слова, а числа берутся целиком: «0,05%» и «14%» отличают одно событие от похожего. idf сглажен, как в scikit-learn, и считается по публикациям последних семи дней. Присоединяемся к сюжету, если публикация похожа на любую его публикацию и вышла не позже чем через 72 часа после неё.

Порог подобран на первом обходе (281 публикация). От 0,45 и выше — одно событие в разных изданиях: «Бензин за неделю подешевел на 0,7%» в Ведомостях и ПРАЙМе, продление лицензии ЛУКОЙЛа в трёх публикациях, тарифы страхования опасных объектов у ЦБ и в Ведомостях. Ниже начинаются соседние темы: выступление министра и заседание Госсовета о промышленности. Окно в 72 часа разводит ежедневные пресс-релизы ЦБ с одинаковыми заголовками («Результаты мониторинга максимальных процентных ставок»).

Карточка сюжета (`representative_id`) — публикация официального источника (`kind: regulator`), иначе первая, при равенстве — где текст полнее. У каждой публикации в `news_dedup` записаны сюжет, способ склейки и сходство. Сюжет дублируется и в `NewsItem.dedup` (`cluster_id`, `duplicate_of`).

Ограничение: сюжеты не склеиваются между собой задним числом. Если два издания написали об одном событии разными словами раньше, чем вышла связывающая их публикация, получится два сюжета. На первом обходе так разошлась недельная инфляция: Ведомости с Коммерсантом и Интерфакс с ПРАЙМом.

```
cd backend
uv run python -m app.news dedup    # сюжеты для новых публикаций
```

## Классификация

Задача A3-04, модуль `app/news/classify.py`. Результат лежит в `NewsItem.classification`, по нему отбор (A4) сопоставляет новость с профилем компании.

| Поле | Что это |
| --- | --- |
| `topics` | тип события, от 1 до 4, главный первым: `key_rate`, `fx`, `regulation`, `commodities`, `logistics`, `labor`, `sanctions` и другие темы `Topic` |
| `segments` | затронутые сегменты рынка — те же id, что у отрасли в профиле (`chemicals`, `logistics`…) |
| `industries`, `regions`, `countries`, `entities` | отрасли словами, регионы России, другие страны, компании и ведомства из текста |
| `sentiment` | знак события для российского бизнеса |
| `horizon` | когда скажется: `days`, `weeks`, `months`, `years` |
| `confidence`, `method`, `model` | уверенность, кто разобрал (`llm` или `rules`) и какая модель |

**Модель.** Разбирает быстрая модель из разрешённого списка: `Task.CLASSIFY` идёт в `LLM_MODEL_FAST` (по умолчанию DeepSeek-V4.1-Flash) через общий клиент с бюджетом. В промпте — закрытые списки тем и сегментов, а ответ — строгий JSON, который проверяется по схеме. Чужие темы и уверенность вне 0–1 — ошибка. Неизвестные сегменты отбрасываются: модель чаще путается в id, чем в сути. Если ответ не прошёл проверку, модель получает текст ошибки и одну попытку исправиться.

**Безопасность.** Текст новости передаётся между маркерами `<<<НОВОСТЬ … НОВОСТЬ>>>`, и в инструкции сказано, что команды внутри текста не исполняются. В модель уходят только источник, дата, заголовок и первые 3000 символов текста.

**Бюджет.** На сюжет (A3-03) — один вызов модели: разбор первой публикации копируется на остальные (`copied_from` в `news_classification`). Там же для каждого разбора записаны число попыток, стоимость и ошибка.

**Без модели.** Если ключ не задан, бюджет исчерпан или провайдер не отвечает, работает запасной разбор по словарю (`method=rules`, уверенность 0,3): ключевые слова тем и сегментов с начала слова, так что «порт» не находится в «импорте». Лента не встаёт. После первого отказа модели остальные публикации обхода сразу разбираются по словарю, без новых попыток. Когда бюджет вернётся, словарные разборы переразбираются моделью:

```
cd backend
uv run python -m app.news classify                  # новые публикации, свежие первыми
uv run python -m app.news classify --retry-rules    # переразобрать словарные моделью
```

Тема `logistics` добавлена в `Topic` и в темы сегмента «Транспорт и логистика»: так новость о тарифах РЖД попадает к перевозчикам и к тем, у кого есть перевозчики среди контрагентов.

Проверено на подменённой модели в тестах. Живой вызов на этой машине не делали: ключа LLM в окружении нет, и первый обход разобран по словарю.
