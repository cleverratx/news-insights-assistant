# Новости

Путь материала: сбор → нормализация → дедупликация → разбор моделью. Аналитика Альфа-Банка идёт отдельным входом и встречается с новостями в общей ленте.

## Сбор

Задача A3-01, модуль `app/news/fetch.py`, список источников — [`backend/app/news/sources.yaml`](../backend/app/news/sources.yaml) (путь задаёт `NEWS_SOURCES_FILE`, относительный — от каталога `backend`).

Рекомендованного списка источников у кейса нет: подходят любые законные бесплатные способы. Берём открытые RSS деловых СМИ и регуляторов.

| Источник | Тип | Текст |
| --- | --- | --- |
| Интерфакс, ПРАЙМ, Коммерсантъ — Экономика, Ведомости — Бизнес, Экономика, Финансы | `media` | в ленте только анонс, качаем страницу статьи |
| Российская газета, Forbes | `media` | полный текст есть в ленте |
| Банк России — пресс-релизы и события, Минпромторг | `regulator` | официальная позиция; у событий ЦБ качаем страницу |
| РИА Новости, Коммерсантъ — Все новости | `media`, резерв | обходятся, только пока недоступны основные (`backup_for`) |
| ТАСС, РБК | `media`, выключены | не отвечают из нашей сети, оставлены для стенда |

### Как обходим

- **Расписание.** У каждого источника свой интервал (`interval_minutes`, по умолчанию `NEWS_FETCH_INTERVAL_MINUTES`). Состояние хранится в таблице `news_sources_state`: когда обходили, когда был успех, сколько ошибок подряд, когда обходить в следующий раз.
- **Ошибки.** Если источник не ответил, следующая попытка будет через 5, 10, 20 минут и так далее, но не реже раза в шесть часов. После трёх ошибок подряд источник считается недоступным, и включаются его резервные.
- **Повторы.** Временные ошибки (таймаут, обрыв, 429, 5xx) повторяются дважды с паузой 1 и 2 секунды. Если сервер прислал `Retry-After`, ждём сколько он просит, но не больше минуты. На 4xx не повторяем.
- **Вежливость.** Между запросами к одному сайту — не меньше секунды. Свой `User-Agent` (`NEWS_USER_AGENT`). robots.txt соблюдаем по правилам Google: группа самого точного User-agent, шаблоны `*` и `$`, побеждает самое длинное правило. Стандартный `urllib.robotparser` для этого не годится: он не понимает `*` и правило `Disallow: /?` (оно есть у Коммерсанта) читает как запрет всего сайта. Нет robots.txt — можно обходить, сайт не ответил — не обходим.
- **Без лишних запросов.** Ссылка приводится к одному виду (без `utm_*`, якоря, хост в нижнем регистре). Страницы статей, которые уже сохранены, повторно не качаются.

### Что сохраняем

Таблица `raw_news` — материал как его отдал источник, без обработки: так нормализацию (A3-02) можно пересчитать, не обходя источники заново.

| Поле | Что это |
| --- | --- |
| `raw_id` | `raw:` + хеш ссылки |
| `source_id`, `url`, `guid` | источник, ссылка на первоисточник, id записи в ленте |
| `title`, `summary`, `feed_text` | заголовок, анонс и полный текст, если лента его отдаёт |
| `html` | страница статьи, если источник отдаёт только анонс |
| `published_at`, `fetched_at` | время публикации по ленте и время сбора, UTC |
| `article_status` | `feed_only` — текст из ленты, `fetched` — страница скачана, `robots` — robots.txt запрещает, `failed` — страница не ответила, `too_large` — больше 3 МБ |

## Нормализация

Задача A3-02, модуль `app/news/normalize.py`. Запись `raw_news` превращается в `NewsItem` (схема — [schemas/news_item.schema.json](schemas/news_item.schema.json)) и сохраняется в таблицу `news_items`: ключевые поля отдельными столбцами, весь материал — в `item` (jsonb).

| Поле | Как получаем |
| --- | --- |
| `id` | `news:` + хеш ссылки, тот же, что у записи `raw_news` |
| `title` | заголовок из ленты без HTML-сущностей и лишних пробелов |
| `text`, `fragments` | текст статьи абзацами; каждый абзац — фрагмент `p1`, `p2`… с пометкой «абзац N», на него ссылаются факты и выводы |
| `summary` | анонс из ленты без разметки, если он не повторяет первый абзац |
| `published_at` | дата из ленты в UTC; если её нет или она из будущего — время сбора |
| `source`, `url` | название и лента источника, ссылка на первоисточник |
| `language` | `ru` или `en` по доле кириллицы и латиницы |
| `dedup.content_hash` | хеш слов заголовка и текста без регистра и пунктуации: точные перепечатки совпадут |

Текст статьи ищем по порядку, способ записан в `text_origin`:

1. `feed` — полный текст из ленты (`content:encoded`, `yandex:full-text`);
2. `selector` — абзацы по CSS-селектору источника (`text_selector` в `sources.yaml`);
3. `json_ld` — `articleBody` из JSON-LD страницы; сплошной текст режется на куски по несколько предложений, чтобы на фрагмент можно было сослаться точно;
4. `generic` — общий алгоритм для источника без селектора. Берутся блоки текста без вложенных блоков, их длина засчитывается родителю и вполовину прародителю, и из узла с наибольшим весом берутся его абзацы. Так тело статьи находится без меню и подвала;
5. `summary` или `title` — если страницы нет.

Служебные строки («Читайте также», «Подписывайтесь», «Фото:», «©») и повторы абзацев отбрасываются.

Селекторы проверены 21.10.2026 на сайтах из списка источников. На первом обходе по селектору разобрано 197 статей из 281, по полному тексту ленты — 19, по JSON-LD — 2. Ещё 63 записи остались только с анонсом: у пресс-релизов ЦБ и новостей Минпромторга в анонсе и так полный текст на 2 тыс. символов, а у Российской газеты страницы качаются начиная с этой задачи.

Сырые записи хранятся, поэтому нормализацию можно пересчитать без нового обхода, например после правки селектора:

```
cd backend
uv run python -m app.news normalize          # новые записи raw_news
uv run python -m app.news normalize --all    # все заново
```

## Дедупликация

Задача A3-03, модуль `app/news/dedup.py`, схема сюжета — [schemas/news_story.schema.json](schemas/news_story.schema.json). Одно событие из пяти изданий — одна карточка-сюжет, а ссылки на все публикации сохраняются списком (`NewsStory.items`). Эмбеддингов нет ([ADR 0002](decisions/0002-otbor-bez-embeddingov.md)), поэтому сравниваем лексически, в два шага:

1. **Перепечатка** (`match=exact`) — совпал `content_hash`: слова заголовка и текста те же. В `duplicate_of` — оригинал.
2. **То же событие** (`match=similar`) — косинус TF-IDF не меньше 0,45. Вектор строится по основам слов заголовка (вдвое весомее) и первых двух абзацев. Основа — первые пять букв слова, а числа берутся целиком: «0,05%» и «14%» отличают одно событие от похожего. idf сглажен, как в scikit-learn, и считается по публикациям последних семи дней. Присоединяемся к сюжету, если публикация похожа на любую его публикацию и вышла не позже чем через 72 часа после неё.

Порог подобран на первом обходе (281 публикация). От 0,45 и выше — одно событие в разных изданиях: «Бензин за неделю подешевел на 0,7%» в Ведомостях и ПРАЙМе, продление лицензии ЛУКОЙЛа в трёх публикациях, тарифы страхования опасных объектов у ЦБ и в Ведомостях. Ниже начинаются соседние темы: выступление министра и заседание Госсовета о промышленности. Окно в 72 часа разводит ежедневные пресс-релизы ЦБ с одинаковыми заголовками («Результаты мониторинга максимальных процентных ставок»).

Карточка сюжета (`representative_id`) — публикация официального источника (`kind: regulator`), иначе первая, при равенстве — где текст полнее. У каждой публикации в `news_dedup` записаны сюжет, способ склейки и сходство. Сюжет дублируется и в `NewsItem.dedup` (`cluster_id`, `duplicate_of`).

Ограничение: сюжеты не склеиваются между собой задним числом. Если два издания написали об одном событии разными словами раньше, чем вышла связывающая их публикация, получится два сюжета. На первом обходе так разошлась недельная инфляция: Ведомости с Коммерсантом и Интерфакс с ПРАЙМом.

```
cd backend
uv run python -m app.news dedup    # сюжеты для новых публикаций
```

## Классификация

Задача A3-04, модуль `app/news/classify.py`. Результат лежит в `NewsItem.classification`, по нему отбор (A4) сопоставляет новость с профилем компании.

| Поле | Что это |
| --- | --- |
| `topics` | тип события, от 1 до 4, главный первым: `key_rate`, `fx`, `regulation`, `commodities`, `logistics`, `labor`, `sanctions` и другие темы `Topic` |
| `segments` | затронутые сегменты рынка — те же id, что у отрасли в профиле (`chemicals`, `logistics`…) |
| `industries`, `regions`, `countries`, `entities` | отрасли словами, регионы России, другие страны, компании и ведомства из текста |
| `sentiment` | знак события для российского бизнеса |
| `horizon` | когда скажется: `days`, `weeks`, `months`, `years` |
| `confidence`, `method`, `model` | уверенность, кто разобрал (`llm` или `rules`) и какая модель |

**Модель.** Разбирает быстрая модель из разрешённого списка: `Task.CLASSIFY` идёт в `LLM_MODEL_FAST` (по умолчанию DeepSeek-V4.1-Flash) через общий клиент с бюджетом. В промпте — закрытые списки тем и сегментов, а ответ — строгий JSON, который проверяется по схеме. Чужие темы и уверенность вне 0–1 — ошибка. Неизвестные сегменты отбрасываются: модель чаще путается в id, чем в сути. Если ответ не прошёл проверку, модель получает текст ошибки и одну попытку исправиться.

**Безопасность.** Текст новости передаётся между маркерами `<<<НОВОСТЬ … НОВОСТЬ>>>`, и в инструкции сказано, что команды внутри текста не исполняются. Перед этим текст проходит фильтр инъекций (A5-10, [llm.md](llm.md#защита-от-инъекций-a5-10)): подделки маркеров обезврежены, предложения-команды скрыты, а при нормализации такой материал получает запись `injection` в журнале. В модель уходят только источник, дата, заголовок и первые 3000 символов текста.

**Бюджет.** На сюжет (A3-03) — один вызов модели: разбор первой публикации копируется на остальные (`copied_from` в `news_classification`). Там же для каждого разбора записаны число попыток, стоимость и ошибка.

**Без модели.** Если ключ не задан, бюджет исчерпан или провайдер не отвечает, работает запасной разбор по словарю (`method=rules`, уверенность 0,3): ключевые слова тем и сегментов с начала слова, так что «порт» не находится в «импорте». Лента не встаёт. После первого отказа модели остальные публикации обхода сразу разбираются по словарю, без новых попыток. Когда бюджет вернётся, словарные разборы переразбираются моделью:

```
cd backend
uv run python -m app.news classify                  # новые публикации, свежие первыми
uv run python -m app.news classify --retry-rules    # переразобрать словарные моделью
```

Тема `logistics` добавлена в `Topic` и в темы сегмента «Транспорт и логистика»: так новость о тарифах РЖД попадает к перевозчикам и к тем, у кого есть перевозчики среди контрагентов.

Проверено на подменённой модели в тестах. Живой вызов на этой машине не делали: ключа LLM в окружении нет, и первый обход разобран по словарю.

## Ключевые факты

Задача A3-05, модуль `app/news/extract.py`. Факты лежат в `NewsItem.key_facts` у карточки сюжета: одна публикация на событие, у остальных публикаций свои абзацы, а событие то же. Это закрывает первый вопрос интерпретации — «что произошло: факты, участники, сроки, причины; подтверждённое отдельно от предположений».

| Поле факта | Что это |
| --- | --- |
| `text` | факт одним предложением |
| `status` | `confirmed` — источник сообщает как свершившееся; `reported` — со слов участника («заявил», «по данным»); `forecast` — прогноз или план; `assumption` — предположение или оценка |
| `source_says` | для `reported` и `forecast` — чьи это слова |
| `fragment_id` | абзац, где это сказано: по нему интерфейс показывает цитату |
| `who`, `when`, `numbers` | участники, когда произошло, цифры точно как в тексте |

**Модель.** Извлекает быстрая модель (`Task.EXTRACT` → `LLM_MODEL_FAST`). Модель видит текст пронумерованными абзацами `[p1]`, `[p2]`…, до 6000 символов. Защита от инструкций в тексте та же, что у классификации: маркеры и прямой запрет. Плохой JSON — одна попытка исправить.

**Проверка по источнику** (критерий 04, минимум фактологических ошибок). Ответ сверяется не только со схемой, но и с текстом:

- абзац `fragment_id` должен существовать;
- каждая цифра факта — из `numbers` и из самого предложения — должна найтись в этом абзаце. Числа сравниваются без разделителей, так что «3 300,5» и «3300,5» — одно число.

Факт, который не прошёл проверку, отбрасывается, а счётчик `rejected` в `news_extraction` показывает, сколько таких было. Так выдуманная моделью цифра не доходит до клиента.

**Без модели.** Первые два предложения лида становятся фактами со статусом `reported`, а если в предложении прогноз — `forecast`, с источником в `source_says`. Подтверждёнными без модели факты не считаем: запасной разбор говорит только «так пишет издание». На первом обходе без ключа LLM так собрано 513 фактов по 260 сюжетам.

```
cd backend
uv run python -m app.news extract                  # факты для сюжетов без фактов
uv run python -m app.news extract --retry-rules    # переразобрать запасные моделью
```

Полный цикл по новостям:

```
uv run python -m app.news fetch && uv run python -m app.news normalize && \
uv run python -m app.news dedup && uv run python -m app.news classify && \
uv run python -m app.news extract
```

## Отказоустойчивость пайплайна

Задача A3-09, модули `app/news/pipeline.py` и `app/news/issues.py`, журнал — таблица `news_issues`. Ограничение 05 кейса: данные неполные и зашумлённые, и это не повод останавливать ленту.

```
cd backend
uv run python -m app.news run              # сбор → нормализация → сюжеты → разбор → факты → сущности
uv run python -m app.news run --no-fetch   # обработать уже собранное
uv run python -m app.news run --loop       # по расписанию источников
```

**Материал.** Проблема каждого материала пишется в лог и в `news_issues` (этап, вид, подробность), а обработка продолжается:

| Вид | Что случилось | Что делаем |
| --- | --- | --- |
| `encoding_fixed` | кракозябры: UTF-8, прочитанный как windows-1251 («РЎР±РµСЂ») или latin-1 («Ð¡Ð±ÐµÑ€») | чиним обратным преобразованием; оно принимается, только если проходит без ошибок и даёт кириллицу, так что нормальный текст испортиться не может |
| `encoding` | в тексте символы, которые не удалось декодировать | оставляем как есть, отмечаем |
| `empty_page` | страница скачана, но текста статьи на ней нет | берём анонс или заголовок из ленты |
| `paywall` | в видимом тексте страницы «Подпишитесь, чтобы дочитать статью» и похожие | оставляем бесплатную часть статьи и отмечаем, что текст неполный |
| `no_date` | в ленте нет даты или она из будущего | берём время сбора |
| `error` | обработка записи упала | остальные записи обрабатываются; после трёх ошибок запись больше не берётся в работу |

- Кодировку страницы теперь определяем сами. Сначала берётся кодировка из заголовка ответа, потом из `<meta charset>`, потом пробуем UTF-8, а если это не он — windows-1251, частую у русских сайтов без указания кодировки. Раньше страница без кодировки в заголовке читалась как UTF-8.
- Признаки платного доступа ищутся в видимом тексте, а не в HTML. Слово `paywall` есть в скриптах и классах многих сайтов и на бесплатных статьях. Реклама подписки («Хотите скрыть рекламу? Оформите подписку») платным доступом не считается.
- Если селектор источника нашёл меньше 300 символов, нормализация пробует JSON-LD и общий алгоритм и берёт самый полный текст. У Ведомостей селектор на части страниц цепляет только подзаголовок, и так 30 статей получили полный текст.

**Запись.** Ошибка одной записи в нормализации, классификации или извлечении фактов пишется в `news_issues` с `kind=error` и не останавливает цикл. В отчётах этапов появилось поле `failed`.

**Этап.** Если этап упал целиком, ошибка пишется в лог и в `news_issues`, а следующие этапы всё равно запускаются и работают с тем, что уже есть в базе. Отчёт `run` содержит итоги каждого этапа, список упавших этапов и сводку проблем за проход.

Проверено 21.10.2026 на живом обходе: 261 материал, ни одной ошибки обработки. Платный доступ отмечен у 13 статей Ведомостей («Вы видите 20% этого материала»), у них в тексте осталась бесплатная часть — 300–1200 символов.

## Маркеры

Задача A3-10, модуль `app/news/markers.py`, поле `Classification.markers`. Маркер — короткая метка новости для фильтров ленты (пункт 10 кейса). Список зафиксирован заранее:

| Маркер | Название | О чём |
| --- | --- | --- |
| `economy_rate` | Экономика и ставка | ключевая ставка, инфляция, ВВП, бюджет, кредиты и облигации |
| `fx` | Валюта | курс рубля и других валют, валютный контроль |
| `regulation_taxes` | Регулирование и налоги | законы, требования регуляторов, налоги и сборы, санкции |
| `trade_duties` | ВЭД и пошлины | экспорт, импорт, пошлины, квоты, торговые соглашения |
| `commodities_prices` | Сырьё и цены | нефть, газ, металлы, зерно, удобрения и цены на них |
| `logistics` | Логистика | перевозки, тарифы РЖД, порты, маршруты и сроки доставки |
| `labor` | Рынок труда | зарплаты, кадры, занятость, мигранты |
| `technology` | Технологии | ИИ, цифровизация, импортозамещение оборудования и ПО |
| `industry_event` | Отраслевое событие | событие отрасли или компании: сделка, запуск, отчётность |
| `incident` | Происшествие | авария, пожар, сбой, кибератака, забастовка, стихийное бедствие |

**Кто ставит.** Маркеры ставит быстрая модель в том же вызове, что и классификацию (A3-04), поэтому лишнего расхода бюджета нет. В промпте — закрытый список с описаниями и прямой запрет придумывать свои. Значения не из списка отбрасываются при разборе ответа. Маркеров от 1 до 3, главный первым.

**Без модели.** Если модель маркеров не дала, недоступна или новость разобрана до появления маркеров, они выводятся из тем классификации: `key_rate` и `inflation` → «Экономика и ставка», `trade` → «ВЭД и пошлины» и так далее. Происшествия и технологии в темах не выделены, поэтому для них есть словарь: «пожар», «авария», «кибератака», «искусственный интеллект»… Происшествие всегда ставится первым маркером.

**Фильтры.** Материал проходит фильтр, если у него есть хотя бы один из выбранных маркеров, а пустой выбор — без фильтра.

- `feed(connection, since, markers)` — свежая лента с фильтром.
- `counts(items)` — число материалов под каждым маркером, для счётчиков у фильтров в интерфейсе.
- Поиск (A3-07) принимает `markers`.

Схема ответа классификации изменилась, поэтому у кеша разборов (A3-08) сменилась версия. Новые разборы пойдут в модель заново, старые останутся в истории кеша.

## Сущности

Задача A3-11, модуль `app/news/entities.py`, таблица `news_entities`. Сущность — компания, персона, отрасль, регион, страна или тема новости с общим ключом:

| Вид | Пример ключа | Откуда в новости | Вес связи |
| --- | --- | --- | --- |
| `company` | `company:банк россии` | участники из классификации и ключевых фактов | 3 |
| `person` | `person:эльвира набиуллина` | то же; «Имя Фамилия» или «И. Фамилия» без признаков организации | 2 |
| `industry` | `industry:chemicals` | сегменты рынка — те же id, что у отрасли в профиле | 1 |
| `region` | `region:татарстан` | регионы из классификации | 1 |
| `country` | `country:китай` | страны, кроме России | 0,5 |
| `topic` | `topic:incident` | маркеры (A3-10) | 0,3 |

**Один ключ — одна сущность.** Названия приводятся к одному виду: без кавычек и ООО/ПАО, в нижнем регистре, «ё» → «е». Частые ведомства сведены словарём синонимов: «ЦБ», «ЦБ РФ», «Центробанк» и «регулятор» → «банк россии», «Минфин России» → «министерство финансов», «РЖД» → «российские железные дороги». У регионов отбрасываются «г.» и «Республика»: «Республика Татарстан» и «Татарстан» — один ключ. Сущности собираются из готового разбора, новых вызовов модели нет.

**Связи между новостями.** `related(news_id)` ищет новости с общими сущностями в окне ±14 дней. Сила связи — сумма весов общих сущностей, связью считается сумма от 2: общая компания или персона. Одна общая тема или отрасль связью не считается, иначе всё связано со всем.

**Связь с профилем.** `profile_entities(profile)` — сущности, по которым новость касается клиента:

- его отрасль;
- отрасли контрагентов и компаний группы;
- регион и регионы связанных лиц;
- конкуренты (A2-17).

`for_profile(profile, since)` возвращает такие новости вместе с тем, что совпало. Названия конкурентов дополнительно ищутся в тексте новости целым словом: так новость о конкуренте находится, даже если её разбирали по словарю, без модели.

Сущности пересобираются этапом `entities` пайплайна за последние 14 дней: разбор новости мог обновиться.

## Карточка оригинала

Задача A3-12, модуль `app/news/cards.py`, схема — [schemas/news_card.schema.json](schemas/news_card.schema.json). Карточка показывает, откуда новость: издание, дата, ссылка на статью и картинка.

**Картинка** (`NewsItem.image`) выбирается при нормализации, первая годная по порядку:

1. из ленты: `enclosure` с типом `image/*`, `media:content`, `media:thumbnail`. У Коммерсанта, Ведомостей и Минпромторга это фото статьи, а `og:image` Ведомостей — сгенерированная карточка для соцсетей с текстом поверх;
2. `og:image` (`og:image:secure_url`), `twitter:image`, `link rel=image_src` со страницы статьи;
3. первая картинка в полном тексте ленты.

Ссылка доводится до абсолютной (`/uploads/a.jpg` → `https://сайт/uploads/a.jpg`) и проверяется: только http(s), без data-URI, SVG, GIF, иконок и путей со словами pixel, counter, logo.

**Логотип вместо фото.** Картинка, которая у одного издания стоит на трёх статьях и больше, — логотип или заглушка сайта, а не фото: в карточку она не идёт. Так отсекается, например, `share-1.jpg` на всех событиях ЦБ.

**Нет картинки — вёрстка та же.** `NewsCard.image` — проверенная ссылка или `null`. У карточки всегда есть `placeholder`: инициалы издания («РГ», «И»), домен статьи и цвет, постоянный у издания. Фронтенду достаточно держать блок картинки фиксированного размера: при `image = null` или ошибке загрузки он показывает placeholder.

`cards(connection, news_ids)` возвращает карточки в заданном порядке, неизвестные id пропускает. Новые картинки из ленты хранятся в `raw_news.image_url`, столбец добавляется автоматически.

Проверено 22.10.2026 на шести источниках: картинка есть у 112 карточек из 159, заглушка ЦБ распознана как логотип, у остальных 47 — placeholder.
