# Данные кейса

Организаторы дают обезличенный набор данных о юридических лицах — клиентах корпоративного бизнеса банка — и связанных с ними физических лицах. Идентификаторы работают только внутри набора и не позволяют определить реальные организации или людей.

## Правила обращения

- Выгрузки не коммитятся. Локально они лежат в `data/raw/`, этот путь закрыт `.gitignore`.
- В `data/samples/` кладём только синтетические строки, собранные вручную, — для тестов и демо.
- Производные витрины (parquet, csv, дампы) тоже не коммитим: они собираются скриптами из `data/raw`.
- В логи и в ответы сервиса не выносим сырые идентификаторы: наружу идёт то, что нужно для вывода.

## Профиль данных и эталонные компании

Два скрипта собирают всё, что нужно знать о выгрузках, и переизбираются в один проход. Руками отчёты не правим — они пересобираются из данных.

```
cd backend
uv run python scripts/profile_data.py ../data/raw/df_Uid_data_hack.csv ../data/raw/df_Fid_Uid_link_hack.csv --out ../docs/data-profile.md
uv run python scripts/pick_demo_companies.py ../data/raw/df_Uid_data_hack.csv ../data/raw/df_Fid_Uid_link_hack.csv -n 3 --out ../docs/demo-companies.md --legend ../data/samples/legends.generated.yaml
```

`profile_data.py` (задача A1-08) проверяет файлы на соответствие приложению 1 кейса, считает заполненность и уникальность каждого поля, распределение выручки, топы отраслей и регионов, долю компаний с каждым продуктом банка и с признаком ФТС, покрытие платежами и число контрагентов на компанию, а в конце отмечает поля-константы и поля с пропусками больше половины строк — их нельзя брать в признаки не глядя.

`pick_demo_companies.py` (задача A1-09) отбирает эталонные компании по пригодности для демо: внешнеэкономическая деятельность, продукты, чувствительные к ставке, число контрагентов, участие в группе, заполненность ключевых полей и выручка уровня крупного бизнеса. Компании берутся из разных разделов ОКВЭД, чтобы ленты заметно отличались. На выходе — карточки с признаками, крупнейшими контрагентами и темами, которые должны отзываться в ленте, плюс заготовка легенды для демо — её заполняем руками в задаче A1-13.

Скрипты ничего не скачивают и не ходят в сеть: на вход — только локальные файлы выгрузки.

## Загрузка в PostgreSQL

Задача A2-01. Модуль `app/data` читает обе выгрузки, чистит значения и одной транзакцией перезаливает таблицы `companies`, `persons` и `payments`. Повторный запуск безопасен: таблицы заменяются целиком, а при ошибке остаются прежними.

```
# в Docker: выгрузки лежат в data/raw, каталог data смонтирован в контейнер
docker compose run --rm api python -m app.data

# локально
cd backend
uv run python -m app.data --companies ../data/raw/df_Uid_data_hack.csv --links ../data/raw/df_Fid_Uid_link_hack.csv
```

`--dry-run` разбирает файлы и печатает отчёт без записи в базу. `--payments` принимает отдельный файл платежей: в выданном файле связей столбцов `PAYER`, `BENEFICIARY`, `PAY_AMT`, `PAY_CNT` нет, хотя кейс их описывает. Если они появятся в файле связей, загрузчик возьмёт их оттуда сам.

Что делает с данными:

| Проблема | Что делаем |
| --- | --- |
| кодировка и разделитель | UTF-8 с BOM или cp1251; разделитель (точка с запятой, запятая, табуляция или вертикальная черта) определяется по заголовку |
| пустые значения | `nan`, `null`, `—`, `н/д`, пробелы и пустые строки → `NULL` |
| флаги `*_MARK`, `FTS_FLAG`, `NEGATIVEMARK` | `1`, `1.0`, `да`, `true` → да; `0`, `нет`, `false` → нет; прочее → `NULL` и запись в отчёт |
| выручка и суммы | пробелы и разряды, запятая или точка как десятичный разделитель, `руб.` → `numeric(20,2)`; отрицательные → `NULL` |
| ОКВЭД | `46,38` → `46.38`, потерянный ноль `1.1` → `01.1`; нераспознанный код → `NULL` |
| `CL_TYPE` | только `CLIENT`, `CLOSE_CLIENT`, `PROSPECT` |
| `FTS_COUNTRY_NAME` | строка «КИТАЙ, ТУРЦИЯ» → массив стран без повторов |
| дубликаты `SYNTHETIC_U` | остаётся строка, где заполнено больше полей |
| строка без идентификатора или с лишними полями | отбрасывается: со сдвинутыми столбцами значения попадут не в свои поля |
| повторные платежи между одной парой компаний | суммируются в одну запись |

Каждый запуск пишет отчёт в таблицу `data_loads` и печатает его: сколько строк прочитано, загружено, отброшено и склеено; какие проблемы найдены, в каком поле, сколько раз и в каких строках файла. Идентификаторов и значений в отчёте нет: только номера строк.

Колонки таблиц названы по-английски, соответствие полям выгрузки — в `COMPANY_FIELDS`, `PERSON_FIELDS` и `PAYMENT_FIELDS` в `app/data/loader.py`. По этой карте профиль показывает, из какого поля взят признак. Физлица и платежи не связаны с `companies` внешним ключом: в выгрузке есть связи с компаниями, которых нет в файле юрлиц, и терять их нельзя.

## Как используем в решении

- Профиль компании собираем из `df_Uid_data_hack.csv`: отрасль и её словесная формулировка, размер, стадия, продукты банка, внешнеэкономическая активность, регион.
- Контрагентов и зависимость от них берём из платежей: кто получатель, кто плательщик, какие объёмы и частота.
- Группу компаний — через `GROUP_ID`: событие про одного участника группы может касаться остальных.
- География — `CITY` и `REGION` у компании, `CITY_NAME` и `RC_NAME` у связанных лиц: региональные новости отбираем по ним.

## Аналитика банка

Организаторы дают материалы Центра макроэкономических исследований Альфа-Банка (обзоры инфляции, ставки ЦБ, рынков, макростатистики, тактический взгляд на квартал). Они лежат в той же ленте, что и новости, но помечены как позиция банка: в выводе ссылка на них отвечает за вопрос «как это оценивает банк».
