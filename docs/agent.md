# Собственный оркестратор

A5-01, `backend/app/agent/orchestrator.py`. Это основа последовательного агента:
планировщик выбирает следующий шаг с учётом накопленных результатов, оркестратор
вызывает инструмент из реестра, сохраняет наблюдение и снова обращается к планировщику.
Готовых агентных фреймворков и новых зависимостей нет.

## Контракт выполнения

`Orchestrator(planner, registry, limits).run(profile, news, objective)` возвращает
`RunResult` с общим `AnalysisContext`: `run_id`, цель, профиль компании, материалы,
выполненные шаги и известная стоимость вызовов планировщика. Перед каждым решением
планировщик получает остаток шагов и времени.

Планировщик реализует `next_step(context, tools) -> Planning`. Решение `Decision` —
`tool` с именем инструмента и аргументами либо `finish` с результатом. `reason` —
короткая цель действия, а не скрытая цепочка рассуждений. После ошибки инструмента
планировщик видит её в следующем контексте и может выбрать другое действие.

Реестр `ToolRegistry.register(name, description, handler)` принимает асинхронный
обработчик `(context, arguments) -> Observation`. В наблюдении — JSON-данные и id
источников. Дубли имён запрещены. Неизвестный инструмент не исполняется: в контекст
попадает ошибка. Реестр фиксируется на начало каждого разбора.

Профиль, материалы, аргументы и результаты копируются. Планировщик и инструмент
получают снимок контекста; результаты добавляет оркестратор. Так изменение чужого
снимка не переписывает журнал и не смешивает параллельные разборы.

## Ограничения

`Limits` по умолчанию: 8 решений планировщика, 60 секунд на весь разбор, 15 секунд
на один инструмент. Завершающее решение тоже расходует шаг. Ошибки и повторы
не обнуляют лимит. Время считается монотонными часами; общий таймаут охватывает
планирование, обращения к LLM с её внутренними ретраями и вызовы инструментов.

Статусы результата:

- `completed` — планировщик завершил анализ; результат в `output`;
- `step_limit` — достигнут предел решений, частичные наблюдения сохранены;
- `timeout` — исчерпано общее время, незавершённая операция отменяется;
- `planner_error` — планировщик недоступен или не вернул допустимое решение.

Ошибка и таймаут отдельного инструмента записываются в `Step`, после них можно
перепланировать. Внешняя `asyncio.CancelledError` передаётся вызывающему коду.
Таймауты кооперативные: обработчики должны использовать async I/O и уважать отмену;
блокирующий синхронный код не следует запускать внутри event loop.

## Подключение LLM

`LLMPlanner` использует существующий клиент A1-07, `Task.INTERPRET` и разрешённую
smart-модель. Дневной бюджет, резервирование расходов, тарифы и ретраи остаются
в `app/llm`. Планировщик получает реестр, профиль, материалы и предыдущие наблюдения.
Если полный контекст превышает лимит клиента, разбор прекращается с `planner_error`;
автоматической обрезки с потерей источников нет.

Стоимость корректного ответа и ответа с невалидным JSON учитывается в контексте.
При ошибке сети точная стоимость может быть неизвестна: учёт резерва в Redis остаётся
за LLM-клиентом; `cost_rub` разбора не является сверкой с балансом провайдера.
В логи пишутся run_id, номер шага, действие, инструмент, статус, длительность и известная
стоимость; тексты источников, сырые ответы модели и детали исключений не логируются.

Пример подключения в асинхронном сервисном коде (профиль и события загружены вызывающим):

```python
from app.agent.orchestrator import LLMPlanner, Orchestrator, ToolRegistry
from app.llm.client import open_llm_client

# register_tools регистрирует ваши async-обработчики, возвращающие Observation.
registry = ToolRegistry()
register_tools(registry)
async with open_llm_client() as llm:
    result = await Orchestrator(LLMPlanner(llm), registry).run(
        profile, news, "Оценить влияние события на компанию"
    )
```

A5-01 не публикует новый HTTP endpoint и не выдаёт `output` за проверенный `Insight`.
Расширенный JSON-протокол и коррекция невалидных вызовов — A5-02, конкретные инструменты —
A5-03, долговременное переиспользование контекста — A5-04, критик — A5-05, сборка
инсайта по шести вопросам — A5-06, постоянное хранение трассировки — A5-08.
