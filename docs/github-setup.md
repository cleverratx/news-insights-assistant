# Настройка репозитория на GitHub

Разовая настройка, которую делает владелец репозитория в первый день. Файлы рулсетов лежат в `.github/rulesets` и хранятся в репозитории, чтобы правила можно было восстановить и обсуждать в PR.

## 1. Репозиторий

- Имя: `alfa-news-insights`, видимость приватная до сдачи.
- Ветка по умолчанию: `main`.
- Settings → General → Pull Requests: оставить только **Allow squash merging**, снять **Allow merge commits** и **Allow rebase merging**. Включить **Automatically delete head branches**.
- Settings → General → Features: включить Issues, выключить Wiki и Projects, если не используем.

## 2. Рулсеты

Settings → Rules → Rulesets → New ruleset → **Import a ruleset**, по одному файлу:

| Файл | Что делает |
| --- | --- |
| `.github/rulesets/01-main-protection.json` | защищает `main`: только PR, один апрув, обязательные проверки `backend` и `frontend`, линейная история, слияние только squash, запрет force-push и удаления ветки |
| `.github/rulesets/02-naming.json` | проверяет имена веток `тип/область-суть` и заголовки коммитов `тип(область): что сделано` на всех ветках, кроме `main` |

То же самое одной командой, если установлен `gh` и есть `jq`:

```
gh auth login
scripts/apply-rulesets.sh <owner>/alfa-news-insights
```

Скрипт создаёт рулсет, а если он уже есть — обновляет его по имени.

Проверки `backend` и `frontend` станут доступны для выбора после первого запуска workflow `.github/workflows/ci.yaml`. Если первый PR создаётся раньше, чем workflow хоть раз отработал, временно переведите `01-main-protection` в Disabled или уберите из него блок `required_status_checks`, а после первой сборки верните.

`bypass_actors` в обоих файлах пустой: правила действуют и на владельца репозитория. Если на сдаче понадобится срочный хотфикс, правило отключается на время руками, а не обходится.

## 3. Доступ жюри

Settings → Collaborators and teams → Add people → `alfa-hack-2026`, роль **Read**.

Доступ выдаём в первый день, а не в день сдачи: приглашение нужно принять, и это не мгновенно. Проверить статус можно там же — приглашение должно смениться на активного участника.

## 4. Что проверить после настройки

- Push напрямую в `main` отклоняется.
- Ветка с именем `test-branch` не создаётся, а `feat/ci-rulesets-check` создаётся.
- Коммит с сообщением `fix` отклоняется, `fix(ci): поправил кэш зависимостей` проходит.
- В открытом PR доступна только кнопка Squash and merge.
- В списке проверок PR видны `backend` и `frontend`.
