# Связи модулей A4/A5 после исправлений

## Поток запросов

1. Интерфейс загружает `GET /api/companies/{id}/feed?role=cfo`.
   Роли A4-11 применяются поверх общего скоринга; региональные правила A4-10 учитывают
   компанию, контрагентов, группу и подтверждённые рынки клиента. A4-09 оценивает показанные карточки.
2. Ответ ленты содержит `snapshot_id`. Сервер хранит оценки, роль и хеши входных данных
   в `feed_snapshots`. Снимок не содержит ключей LLM.
3. Кнопка «Разобрать событие» отправляет `news_ids`, `role`, `feed_snapshot_id` в
   `POST /api/companies/{id}/insights`. Баллы от клиента не принимаются.
4. API проверяет компанию, роль и неизменность профиля/материалов. При изменениях — 409
   с просьбой обновить ленту. Совпавший снимок используется без нового вызова A4-09.
5. A5-01–A5-05 запускают оркестратор, JSON-протокол, необходимые инструменты,
   общий контекст и критика. Инструменты выбираются по необходимости, а не все подряд.
6. A5-06/A5-07 формируют шесть разделов с отдельным происхождением утверждений.
   Роль и оценки входят в контекст модели как оценки, а не как подтверждённые факты.
7. A5-08 сохраняет результат и трассу. `ranking` в ответе и трассе содержит те же
   важность, влияние и релевантность, что в исходной карточке. GET трассы LLM не вызывает.

`GET /api/companies/{id}/related-feed` остаётся отдельной лентой A4-12. Она доступна
в интерфейсе, и из её карточки тоже можно запустить анализ. У этой ленты нет ранее
посчитанной оценки A4-09; при открытии используются явно отмеченные оценки правил.

POST без снимка поддерживается для прямого вызова API: роль применяется, важность
рассчитывается общей функцией, влияние — правилами с низкой уверенностью.
`usage` генерации не включает ранее оплаченные вызовы построения ленты.

## Региональные правила

- Собственный регион и регионы контрагентов дают подтверждённую связь с профилем.
- `markets.regions` из клиентской базы знаний читается из соответствующего признака;
  значение — регионы через запятую, точку с запятой, вертикальную черту или перевод строки.
  Произвольные тексты других фактов не интерпретируются как подтверждённая география.
- При чужом регионе применяется коэффициент 0,65 с объяснением в скоринге.
- Чисто региональная новость без иных совпадений остаётся фоновым кандидатом с малым
  весом; она не тратит слот проверки релевантности моделью. Низкий балл больше не
  отсекает её до формирования фоновой выдачи.
- Общий фильтр важности продолжает действовать. Для показа фона — `min_importance=0`;
  интерфейс предлагает переключатель «Региональный фон».

## Проверки и пределы проверки

Тесты проверяют перенос оценок и роли, запрет снимков другой компании, изменение
профиля/материала, 409 при устаревшей роли, сохранение снимков в настоящем PostgreSQL,
учёт рынков клиента, региональный фон и сквозной POST → инструменты → критик → GET trace.
Фронтенд проверяется TypeScript, production-сборкой и ESLint.

Старый `eval/snapshot_llm` был размечен для прежнего ранжирования. После изменения
региональных коэффициентов меняются промпты и выдача: исторические ответы LLM не
подтверждают качество нового ранжирования. Тест проверяет, что отчёт честно показывает
отсутствие новых вердиктов и неразмеченные пары; файлы ответов не подделывались.
Для нового замера качества нужны новые ответы и дополнение ручной разметки.
В автоматических тестах внешняя LLM подменяется.
