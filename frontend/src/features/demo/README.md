# Переключение демо-компании (A6-08)

В шапке интернет-банка доступен выбор демо-компании. В списке видны название,
отрасль и регион из `GET /api/companies/{company_id}/profile`. Без легенды
показывается идентификатор. Над лентой расположен краткий профиль: отрасль,
регион, выручка, кредитные продукты и ВЭД, если они есть в ответе API.

По умолчанию используются компании, отобранные в A1-09 и описанные в
[docs/demo-companies.md](../../../../docs/demo-companies.md): `U_185947`,
`U_19717`, `U_3263`. Список задаётся существующей переменной `VITE_DEMO_COMPANIES`.
Для синтетических данных из `data/samples`:

```powershell
$env:VITE_DEMO_COMPANIES = 'U_900001,U_900002,U_900003'
npm.cmd run dev
```

## Поведение

- Компания и должность хранятся в URL: перезагрузка, прямая ссылка и история
  браузера восстанавливают выбор. Неизвестная компания заменяется первой демо-компанией.
- Смена компании сохраняет должность, период, фильтры и вкладку для сравнения
  в одинаковых условиях. Фильтры могут скрыть все события; их можно сбросить в ленте.
- Из разбора события переключение открывает `/feed` и удаляет `snapshot` и
  `basis`: снимок прежней компании и открытые источники к новой не относятся.
  На главной и в ленте маршрут сохраняется.
- Существующий API ленты получает новый `company_id`. Кэш разделён по компании,
  должности и параметрам запроса; во время загрузки прежняя лента не показывается.
  Повторный выбор текущей компании ничего не перезапускает.
- Недоступный профиль отмечается в списке. Компанию по-прежнему можно выбрать:
  лента и профиль загружаются независимо, в профиле доступна кнопка «Повторить».
- Фронтенд не подменяет новости заготовками и не отправляет запрос генерации
  разбора при смене компании. Получение ленты может задействовать LLM на сервере
  по существующей логике API.

## Проверка

1. Войти под демо-пользователем и открыть «Новости для бизнеса».
2. Последовательно выбрать три компании в шапке: должны меняться профиль,
   запрос `/api/companies/{company_id}/feed`, события и их релевантность.
3. Установить должность и фильтры, сменить компанию: условия сравнения сохраняются.
4. Открыть событие, сменить компанию: должна открыться её лента без `snapshot`
   в URL. Запроса `POST /insights` для новой компании быть не должно.
5. Проверить перезагрузку и «Назад/Вперёд», затем быстро переключить несколько
   компаний при медленной сети: чужие события не должны появляться в текущей ленте.
6. Проверить пустую ленту, недоступный профиль, повтор загрузки и выбор без легенды.

Автоматические проверки: `npm run lint`, `npm run typecheck`, `npm test`,
`npm run build`. `tests/demo-context.test.mjs` проверяет восстановление контекста,
очистку снимка, сохранение фильтров, невалидный выбор и признаки профиля без платных запросов.
