# Новостная аналитика для принятия бизнес-решений

Сервис, который превращает поток новостей и аналитику Альфа-Банка в персональные выводы для руководителя конкретной компании: что произошло, почему это важно именно ему, что может произойти дальше и что с этим делать.

## Что будет уметь

- Собирать новости из открытых источников и держать их в одной ленте с аналитическими материалами банка.
- Строить профиль компании-клиента по выгрузкам кейса: отрасль, размер, продукты банка, регионы, контрагенты, группа компаний.
- Отбирать из потока то, что касается именно этой компании, и объяснять связь, а не просто совпадение слов.
- Отвечать на шесть вопросов качественной интерпретации: что произошло, почему важно этой компании, какие последствия возможны, какие действия релевантны, как это оценивает банк, на чём основан вывод.
- Показывать источник каждого утверждения: новость, признак клиента или аналитика банка.

## Как это устроено

Бэкенд — сервис на Python 3.12 и FastAPI: сбор новостей, профиль клиента, отбор и ранжирование, агент и API. Фоновые задачи — на arq и Redis, хранилище — PostgreSQL. Агентная логика (планирование, вызов инструментов, общий контекст, самопроверка) написана нами: готовые мультиагентные фреймворки кейс запрещает как основной компонент решения.

Фронтенд — React и TypeScript, сборка через Vite. Типы запросов к API берутся из OpenAPI-документа бэкенда.

LLM — только из списка, разрешённого организаторами, через общий ключ с дневным лимитом. Подробности — в [docs/llm.md](docs/llm.md).

## Быстрый старт

```
cp .env.example .env

docker compose up -d --build --wait
```

Интерфейс — на `localhost:8080`, API — на `localhost:8080/api`, схема — на `localhost:8080/api/docs`.
Без ключа LLM доступны каркас интерфейса и проверка живости API.

Состав сервисов, переменные окружения и команды управления — в [deploy/README.md](deploy/README.md).
Локальный запуск без Docker и команды проверок — в [docs/development.md](docs/development.md).

## Как мы работаем

`main` всегда зелёный: прямых коммитов нет, изменения приходят через PR с пройденными проверками `backend`, `frontend` и `deployment`. Ветка живёт недолго и решает одну задачу, имя — `тип/область-суть`, например `feat/news-rss-collector`. Коммиты и заголовок PR — `тип(область): что сделано`, по-русски. Вливаем только Squash and merge, поэтому заголовок PR становится единственным коммитом в `main`. Подробности — в [docs/contributing.md](docs/contributing.md).
