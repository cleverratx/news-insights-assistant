# Прогон на новостях вне разметки

Задача A4-07, критерий кейса 5: устойчивое качество на ранее не показанных новостях, без заготовленных сценариев. Проверяем две вещи. Первая — лента на новых новостях не пустая и не ломается, в том числе когда модель недоступна или данные зашумлены. Вторая — качество отбора не хуже, чем на эталоне A4-06 ([relevance.md](relevance.md)).

## Итог

- **Лента не ломается.** 7 сценариев × 3 компании = 21 прогон, нарушений инвариантов 0. Лента не пустая ни в одном прогоне, включая «модель недоступна», «модель вернула не JSON» и зашумлённые данные.
- **Качество держится.** На отложенных новостях P@5 = 53% против 27% у обычной ленты, на эталоне было 33% против 7%. Лента подняла в первые пятёрки все релевантные материалы, которые нашлись в наборе.
- **Слабое место — нет порога значимости.** Когда релевантного мало, лента всё равно добирает 20 карточек. В первые пятёрки попали военные новости: атака дрона на автобус ЗАЭС у оптовика продуктов, перехват «Герани» у производителя медтехники. Это тот же словарный разбор, что и в A4-06, плюс отсутствие нижней границы балла. Не ломается, но выглядит плохо.

В каждом прогоне проверяется:

- лента собирается без исключений и проходит контракт `Feed`;
- лента не пустая;
- места идут подряд, нет повторов материала и сюжета;
- все карточки — из поданных материалов;
- в ленте нет материалов без разбора и без совпадений с компанией;
- у каждой карточки есть объяснение и хотя бы один признак компании, и все признаки есть в профиле;
- вклады признаков сходятся с итоговым баллом (±0,02), балл от 0 до 1;
- нет трёх карточек подряд об одном событии, если было чем их развести;
- флаг `verified` соответствует сценарию.

Что значат сценарии:

| Сценарий | Что подаём |
| --- | --- |
| Только новые новости | отложенный набор, без модели |
| Новые новости и аналитика банка | плюс 9 материалов Альфа-Банка |
| Только за последние сутки | окно ленты `days=1` |
| Модель недоступна | модель отвечает `Budget has been exceeded`, лента должна уйти в порядок правил |
| Модель вернула не JSON | модель дважды отвечает текстом, лента должна уйти в порядок правил |
| Модель подтвердила кандидатов | тестовая модель подтверждает всех. Ожидаем `verified=true` и 10 карточек: модель проверяет первую десятку, непроверенные скрыты |
| Зашумлённые данные | у каждой шестой новости нет разбора, у других нет аннотации, ссылки и картинки, текст на английском, дата из будущего, повтор публикации под другим id |

Тестовые модели — заглушки внутри скрипта. Живая модель в прогоне не участвовала.

**Как читать.** Методика и критерии разметки — те же, что в [relevance.md](relevance.md). Набор меньше: по каждой компании первые 5 карточек ленты, первые 5 обычной ленты и 5 случайных новостей, всего 41 пара. Разметка слепая, разметчик — Claude, как и в эталоне, поэтому нужна проверка человеком.

- **P@5 выше, чем на эталоне, и равен потолку.** Все релевантные материалы, которые нашлись в наборе, лента поставила в первые пятёрки. Выводить отсюда «на новых новостях стало лучше» нельзя: выборки маленькие (15 мест), интервалы широкие.
- **«Прямых» новостей в отложенном наборе нет.** Самые важные события дня — прогноз по ставке, сильное движение курса — попали в эталонную разметку и из отложенного набора исключены. Осталось в основном «косвенное». Потолок здесь 53%, а не 100%: даже идеальная лента не нашла бы пятёрку релевантных.
- **Ошибки в пятёрках** — военные новости и событийный шум («пресс-конференция ЦБ состоится», «конференция исследователей»). Источник тот же, что в A4-06: словарный разбор.

## Что это значит для кейса

1. Сбоев нет: лента устойчива к новым новостям, падению модели и грязным данным. Это закрывает «не ломается» в критерии 5.
2. Персонализация держится и на новых данных: первые пятёрки компаний пересекаются на 16%, у обычной ленты — 100%.
3. Слабое место — показ мусора, когда хорошего мало. Нужен порог значимости: лучше 3 карточки, чем 20 с войной и спортом. Это та же рекомендация, что в A4-06 (пункт 3), здесь она подтверждена на новых данных. Ограничение кейса прямо говорит, что показ нерелевантного критичен.

## Ограничения

- Свежих новостей, вышедших после эталонного снимка, всего 5: сбор шёл через 25 минут после него. Остальные 181 — публикации того же периода, которых не было в разметке. Для критерия «ранее не показанные» это честно: на них система не настраивалась и их не видел разметчик. Но это не «новости завтрашнего дня». Повторить прогон через несколько дней — одна команда, см. ниже.
- Компании те же синтетические, разбор — словарный, модель — заглушки (см. [relevance.md](relevance.md)).

## Как повторить

```
cd backend
uv run python scripts/eval_holdout.py checks --write   # инварианты по снимку; код выхода 1, если есть нарушения
uv run python scripts/eval_holdout.py score --write    # precision@5 по разметке
```

Новый отложенный набор (нужна база со свежими новостями; размеченные публикации эталона исключаются сами):

```
uv run python -m app.news run
uv run python scripts/eval_holdout.py freeze
uv run python scripts/eval_holdout.py checks --write
uv run python scripts/eval_holdout.py pool               # перезапишет labels.csv
```

Прогон инвариантов на сохранённом снимке входит в тесты бэкенда (`tests/test_eval_holdout.py`), поэтому поломка ленты на этих данных уронит CI.
