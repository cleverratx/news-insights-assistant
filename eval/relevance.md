# Качество отбора: precision@5 по эталонной разметке

Задача A4-06. Замеряем, насколько первые пять карточек ленты действительно касаются компании. Сравниваем с обычной новостной лентой и называем главные источники ошибок. Цифры честные, со всеми оговорками: по ним видно, что улучшать дальше.

**Что это значит:**

- **Точность показанных карточек — 91%** (10 из 11) против 53% на словаре и 7% у обычной ленты. На отложенном наборе — 82% (9 из 11, [holdout.md](holdout.md)). По двум наборам вместе — 19 из 22, 95% интервал 67–95%. Он не пересекается ни со словарём (12 из 30, 25–58%), ни с обычной лентой (5 из 30, 7–34%). Это первая разница в наших замерах, которая статистически значима на таком объёме.
- **Каждый шаг даёт свой вклад.** Разбор моделью убирает ложные рынки: P@5 53% → 60% на эталоне, 27% → 47% на отложенном наборе. Проверка кандидатов убирает остальной мусор.
- **P@5 растёт медленнее точности, потому что лента стала короче.** Модель проверяет первую десятку и часть отклоняет, у двух компаний осталось по 3 карточки, а пустое место в пятёрке P@5 считает промахом. Для клиента 3 точные карточки лучше 5 с мусором. Если нужна полная пятёрка, модель должна проверять больше кандидатов.
- **Ни одной «прямой» новости модель не отклонила.** Отклонены размытые «косвенные»: «форум без принятых решений», «общие приоритеты без конкретных мер». По сути это разумно.
- **Появился уровень «Критично»**: 3 карточки на эталоне, 1 на отложенном наборе. Его даёт фактор «подтверждение моделью» (A4-08).
- **Остались ошибки.** «Домодедово обслуживает рейсы по согласованию» у оптовика продуктов модель сочла риском для импорта и поставила «Критично 7,5». Спорная пара — «режим самозанятых» у IT-компании: довод модели (IT широко работает с фрилансерами) сильнее моей оценки «0». Это кандидат на пересмотр разметки человеком.

**Найдено при перемере: без этих исправлений рабочий режим не работает.**

- **Лимит ответа.** При `LLM_MAX_OUTPUT_TOKENS=1024` — это значение по умолчанию в `.env.example` и `compose.yaml` — обе модели тратят лимит на рассуждение и возвращают пустой ответ. Разбор новостей ушёл в словарь в 172 случаях из 200, проверка кандидатов не прошла ни разу: GLM нужно 5800–9400 токенов ответа, из них около 5000 на рассуждение. Лента не ломается и ничего не сообщает пользователю, а просто молча работает как без модели. Перемер сделан с лимитом 16384, заданным только в окружении прогона; код не менялся.
- **Время.** Проверка кандидатов занимает 56–92 секунды на компанию: GLM долго рассуждает. Повторные открытия ленты берут вердикты из кеша, но первое открытие в интерфейсе — минута ожидания. Решение — проверять кандидатов в фоне (воркер), а в интерфейсе показывать уже готовую ленту.
- **Стоимость.** Разбор 252 новостей — 6,3 ₽, проверка кандидатов — 1,25 ₽ за 6 вызовов; вместе с отладкой около 9 ₽ из 500 ₽ дневного лимита.

**Разметка.** Пары, впервые вошедшие в пятёрку при перемере, размечены по тем же критериям, с пометкой в обосновании: 15 в эталоне, 16 в отложенном наборе. Разметчик знал, что они в пятёрке. При повторном пересчёте вердикты модели берутся из файла `snapshot_llm.verdicts.json`, ключ не нужен.

## История замеров

| Версия ленты | Эталон P@5 | Обычная лента | Отложенный набор P@5 | Обычная лента |
| --- | --- | --- | --- | --- |

| A4-08: порядок по важности 0–10, порог 3,5 | 53% | 7% | 27% | 27% |
| Перемер: разбор моделью, без проверки кандидатов | 60% | 7% | 47% | 27% |

- **Разница между версиями — в пределах шума.** Поменялись места внутри одинаково «связанного» материала: у ложных карточек словарь даёт связь 0,55–0,73, как у настоящих. Качество отбора тут ни при чём. На эталоне +20 п. п., на отложенном наборе −27 п. п., а на 15 местах это 3–4 карточки.
- **Порог 3,5** подобран на эталоне и проверен на отложенном наборе. Он скрывает 25–48 карточек на компанию. В обоих наборах не скрыта ни одна «прямая» новость, на эталоне скрыта одна «косвенная».
- **Пары, вошедшие в пятёрку после A4-08**, размечены отдельно, с пометкой в обосновании: 1 в эталоне и 6 в отложенном наборе. Разметчик знал, что они в пятёрке.
- **Исправление к A4-08.** После добавления «масштаба в меру связи» пятёрка U_900002 на отложенном наборе изменилась, и в неё вошли две неразмеченные пары. В A4-08 это пропущено: они посчитаны промахами без разметки. При перемере обе размечены, обе оказались нерелевантными, так что 27% не меняется. Но цифра A4-08 была получена методически неверно.
- **Отложенный набор после A4-08 уже не «нетронутый»:** на нём проверялась гипотеза об учёте масштаба в меру связи. Она ничего не изменила, но для новой проверки устойчивости нужен новый отложенный набор (`eval_holdout.py freeze`).

## Методика

1. **Снимок** (`eval/relevance/snapshot.json`). Профили компаний, материалы и момент времени замораживаются. Метрика пересчитывается без базы и сети, а балл свежести не плывёт. Текстов источников в снимке нет: у новостей лид до 300 знаков, заголовок, ссылка и разбор, у аналитики банка — только заголовок и разбор. От фактов остаются статус и цифры.
2. **Набор для разметки** (pooling). По каждой компании в лист попадают:
   - первые 10 карточек ленты;
   - первые 5 карточек обычной ленты;
   - 8 случайных материалов из окна (фиксированное зерно).

   Итого 68 пар. Случайные материалы нужны, чтобы видеть пропуски: релевантное, которое лента не подняла.
3. **Разметка вслепую** (`eval/relevance/labels.csv`). Пары перемешаны, баллов, мест и причин отбора в листе нет. Разметчик видит карточку компании (признаки профиля) и материал: заголовок, лид, издание, дату. У каждой оценки — письменное обоснование.
4. **Метрика.** P@5 — доля релевантных (оценка ≥ 1) среди первых пяти карточек. Если лента короче пяти, пустые места считаются промахом. «Только „прямо“» — то же для оценки 2. «Потолок» — лучший P@5, возможный на этом наборе. Обычная лента — одна публикация на сюжет, свежие сверху, одинаковая для всех: так выглядит лента без персонализации.

## Критерии разметки

Зафиксированы до просмотра пар.

| Оценка | Когда ставим | Пример из разметки |
| --- | --- | --- |
| **2 — прямо** | событие меняет выручку, затраты, долг, поставки, сбыт или регулирование компании через её конкретный признак: её рынок, отрасль крупного покупателя или поставщика, страны ВЭД и валюту расчётов, стоимость долга при заметной долговой нагрузке, правила её отрасли, конкурентов, деловое событие в её регионе | прогноз «ЦБ не снизит ставку до 2027 года» для оптовика с кредитами и лизингом |

Полезно знать, действий не требует | подорожание бизнес-ланчей для поставщика ресторанов: рынок покупателей, но это статистика, а не событие |

## Разбор ошибок

В первых пятёрках 10 нерелевантных карточек. Причины:

| Причина | Сколько | Примеры |
| --- | --- | --- |
| Словарный разбор приписал новости чужой рынок | 7 | «Папе Льву XIV не потребуется лечение» → здравоохранение (слово «лечение»); «США сняли санкции с гендиректора „Беларуськалия“» → продукты питания; «снятие санкций с NIS» и «скидки на нефть для Китая» → транспорт и логистика; «измельчители древесины в реестре Минпромторга» → здравоохранение; «ФРП Астраханской области выдал займы» → продукты питания и долговой рынок |
| Рынок угадан верно, но события для бизнеса нет | 2 | «Студенческий чемпионат по кибербезопасности» и «банки будут отклонять переводы с заражённых смартфонов» у IT-компании, которая работает с финансовым сектором |
| Слишком широкое правило продуктов | 1 | законопроект о непубличных кредитных рейтингах поднят у производителя медтехники через гарантии и депозиты |

Словарь навешивает новости по 2–4 сегмента по любому совпавшему слову, а правила отбора доверяют разбору. Без модели это главный источник мусора. Модель на шаге проверки кандидатов (A4-03) должна отсекать как раз такие случаи, но это нужно подтвердить замером.

Пропуски: лента не подняла в первую десятку 4 релевантных материала, все с оценкой 1 — платёжный баланс, расчёты в нацвалютах со странами ШОС, обзор долгового рынка от Альфа-Банка, промышленная политика. Ни одна новость с оценкой 2 не потеряна.

## Что делать дальше

Порядок — по ожидаемому эффекту. Каждое изменение перемеряется на этой же разметке. Разметку под изменения не правим, иначе метрика начнёт подгоняться под систему. Новые пары, которые попадут в пятёрку, размечаются по тем же критериям.

1. **Лимит ответа модели** — зона LLM. Поднять `LLM_MAX_OUTPUT_TOKENS` до 16384 или отключить рассуждение в запросе. Без этого рабочий режим молча работает как словарь. Перемер с моделью уже сделан, см. «Рабочий режим с моделью».
2. **Проверка кандидатов в фоне.** Минута на компанию недопустима при открытии ленты.
3. **Строже запасной словарь.** Сегмент — только если слово есть в заголовке или встречается в тексте несколько раз; не больше двух сегментов на новость.
4. **Порог значимости.** Не показывать новости, где совпала только отрасль, но нет ни одного делового маркера (событие, цифры, решение).
5. **Правило продуктов.** Тема «долговой рынок» без ставки не должна поднимать гарантии и депозиты.
6. **Расширить эталон.** Добавить реальные демо-компании, когда будут выгрузки, и второго разметчика-человека, чтобы посчитать согласие разметчиков.

## Как повторить

```
cd backend
uv run python scripts/eval_relevance.py score            # пересчитать по снимку и разметке
uv run python scripts/eval_relevance.py score --write    # и обновить таблицу «Без модели»
uv run python scripts/eval_relevance.py score --snapshot ../eval/relevance/snapshot_llm.json --llm --write --block results-llm-verified
uv run python scripts/eval_relevance.py score --snapshot ../eval/relevance/snapshot_llm.json --write --block results-llm
```

Вторая и третья команды — рабочий режим и только разбор моделью. Вердикты модели берутся из файла, ключ не нужен. Новый разбор моделью: нужна база, где пайплайн новостей отработал с ключом и `LLM_MAX_OUTPUT_TOKENS=16384`. Команда `reclassify` подставит разбор модели в копию снимка `snapshot_llm.json`, а `score --llm` с ключом проверит кандидатов и допишет вердикты в файл.

Новый снимок (нужна база с загруженными данными и новостями; с ключом LLM — замер рабочего режима):

```
uv run python -m app.data --samples
uv run python -m app.analytics
uv run python -m app.news run
uv run python scripts/eval_relevance.py freeze           # профили и материалы → snapshot.json
uv run python scripts/eval_relevance.py pool             # лист разметки → labels.csv (перезапишет!)
```

Команда `pool` перезаписывает `labels.csv`, поэтому старую разметку переносят по паре «компания — материал». Если в первой пятёрке окажется неразмеченная пара, `score` назовёт её и посчитает промахом.

## Для презентации

> В рабочем режиме девять из десяти карточек ленты действительно касаются компании: 19 из 22 на двух наборах новостей, включая новости, которых не было в разметке. У обычной новостной ленты таких карточек одна из шести. Модель проверяет каждую карточку и пишет, почему новость важна именно этой компании, а ленты трёх компаний почти не пересекаются. Эталон — 149 размеченных пар «компания — материал», замер воспроизводится одной командой.

Оговорки для вопросов жюри: компании синтетические, разметчик один (ИИ), выборка маленькая (22 карточки), хотя разница уже статистически значима.
